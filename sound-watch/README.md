# sound-watch — 집 안 소리 알림 + 층간소음 기록 리포트

서랍 속 갤럭시 S21을 **방 안의 귀**로 쓰고, 윈도우 PC가 판단합니다.

```
S21 (마이크) ── 16 kHz Int16 PCM, 1초마다 POST ──▶ PC (sound-watch)
                                                    ├─ (a) 소리 인식 → ntfy / s21-sidekick 알림
                                                    └─ (b) 소음 레벨 상시 기록 → sqlite → HTML/CSV 리포트
```

- **(a) 소리 이벤트 알림**: 세탁기/건조기 종료 멜로디, 밥솥 완료음, 초인종, 노크(택배), 전자레인지 '띵', 끓는 주전자 휘파람. 내 집 소리를 **한 번 녹음해 등록**하면(템플릿) 그 소리가 날 때 폰/PC로 알려줍니다. 범용 노크 감지기와 삐/멜로디 감지기도 있습니다.
- **(b) 층간소음 로그**: 100 ms마다 A-가중 레벨을 재서 기준을 넘는 구간을 시각·지속시간·대략의 dB(A)상당 값으로 기록하고, **증거 스타일 리포트**(일/주 표, 타임라인, 야간 22–06시 건수, 상위 이벤트)를 만듭니다.
- Python 3.9+ **표준 라이브러리만**으로 동작합니다. numpy가 있으면 FFT만 빨라집니다(선택, 없어도 모든 기능 동일).
- 이 도구의 측정값은 **교정된 소음계가 아닙니다.** 아래 [측정의 한계](#측정의-한계와-공식-절차)를 꼭 읽어 주세요.

## 빠른 시작 (윈도우 PowerShell 기준, 맥/리눅스는 `python3`)

```powershell
cd sound-watch
python -m soundwatch serve            # 처음 실행하면 data\config.json 과 무작위 토큰을 만들고 접속 주소를 보여 줍니다
```

콘솔에 이런 줄이 나옵니다.

```
폰에서 열기: http://127.0.0.1:8770/#token=<토큰>
```

폰에서 열 때는 아래 [S21에서 열기](#s21에서-열기)를 보세요(마이크는 HTTPS 또는 localhost에서만 허용됩니다).

## 1. 소리 등록 (enroll)

각 소리를 **스마트폰 녹음기 등으로 한 번 녹음**해 WAV로 옮깁니다. 앱이 m4a만 내보내면 무료 변환기로 WAV(16비트 PCM)로 바꾸세요. (부동소수/압축 WAV는 읽지 않습니다. 샘플레이트·스테레오는 자동 변환.)

```powershell
python -m soundwatch enroll 초인종 doorbell.wav --say "초인종이 울렸어요"
python -m soundwatch enroll 세탁기 washer_done.wav --say "세탁이 끝났어요" --cooldown 120
python -m soundwatch enroll 밥솥 cooker.wav --say "밥이 다 됐어요"
python -m soundwatch templates                    # 목록
python -m soundwatch templates --remove 밥솥       # 삭제
```

녹음 요령
- **소리 앞에 1초 이상 배경 소리(무음)만** 있게, 뒤에도 1초 남기세요. 배경 소음은 그 구간으로 추정하고, 등록 직후 같은 파일로 자체 검증도 합니다.
- 같은 이름으로 **2~3번 더 enroll**하면 샘플이 늘어나고 일치 임계값이 샘플 간 편차에 맞춰 자동 조정됩니다.
- 한 파일에 소리 덩어리가 여러 개(예: 3초 이상 간격)면 가장 뚜렷한 하나만 씁니다(안내 메시지가 나옵니다).
- 쿨다운(`--cooldown`, 기본 30초)은 같은 소리의 반복 알림을 막습니다. 건조기처럼 몇 분마다 멜로디를 반복하면 길게 잡으세요.
- `--threshold`(0~1, 낮을수록 엄격, 기본 0.35). 놓치면 올리고, 오탐이 있으면 내리세요.
- 서버가 떠 있는 중에 enroll해도 됩니다. 5초 안에 자동으로 다시 읽습니다.

파일을 미리 시험해 보기:

```powershell
python -m soundwatch analyze test.wav          # 레벨, 소음 이벤트, 소리 인식 결과를 출력
python -m soundwatch analyze test.wav --json
```

### 인식이 동작하는 방식
1. 50 ms 슬라이스마다 FFT(자체 라딕스-2, numpy 있으면 빠른 경로)로 멜 간격 24밴드 에너지, 지배 주파수(포물선 보간), 스펙트럼 평탄도, 피크 집중도를 구합니다.
2. 밴드별 **배경 추정**(최근 8초의 20% 분위수)보다 충분히 튀는 밴드만 남겨 '활성 프레임'과 단위벡터 지문을 만듭니다 → 음량·배경 소음에 둔감.
3. 등록 소리의 프레임열과 실시간 프레임열을 **스트리밍 부분수열 DTW**(대각/수평/2행 점프, 0.5~2배 속도 변화 허용)로 비교합니다. 프레임 비용 = 밴드 지문 코사인 거리와 음정(반음) 차이의 가중합. 점수(0 완벽 ~ 1 불일치)가 임계값 이하이고, 나쁜 프레임이 30% 이하이며, 길이가 0.5~2배일 때 일치로 봅니다.
4. 최저점이 확정되면(0.2초 개선 없음) 한 번 알리고 쿨다운에 들어갑니다.
5. **노크**: 10 ms 포락선의 급상승 + 120 ms 안 10 dB 이상 감쇠(충격성) + 순음이 아님, 이런 타격이 일정한 리듬으로 3회 이상(`detectors.knock.min_hits`). 
6. **삐/멜로디**: 음정이 안정적인 순음 구간을 묶어 'beep'/'melody'로 기록. 등록한 템플릿이 같은 소리를 이미 잡았으면 중복으로 알리지 않습니다. 기본적으로 알림은 끄고(기록만) 켜려면 `detectors.beep.notify: true`.

## 2. 알림 설정

`data\config.json` (처음 `serve` 때 생성, 일부만 적어도 나머지는 기본값):

```json
{
  "notify": {
    "console": true,
    "ntfy": {"enabled": true, "server": "https://ntfy.sh", "topic": "내가-정한-추측-어려운-토픽", "token_env": "NTFY_TOKEN"},
    "sidekick": {"enabled": true, "url": "http://127.0.0.1:8765", "token_env": "SIDEKICK_TOKEN", "module": "sound-watch"}
  }
}
```

- **ntfy**: JSON 발행 API(`POST <server>/`, UTF-8)로 보냅니다. 공개 ntfy.sh의 토픽은 이름을 아는 누구나 구독할 수 있으니 추측하기 어려운 이름을 쓰거나 직접 호스팅하세요. 인증이 필요하면 토큰을 **환경변수**(`NTFY_TOKEN`)로 넘기세요(설정 파일에 쓰지 않습니다).
- **s21-sidekick**: 같은 폰/다른 폰의 sidekick 서버에 `POST /api/say` (`X-Sidekick-Token` 헤더, 본문 `{"text","module"}`)로 보내면 폰이 소리 내어 읽어 줍니다. 토큰은 환경변수 `SIDEKICK_TOKEN`(sidekick의 `server.token` 값). sidekick은 분당 12회·최소 1초 간격 제한이 있어 넘치면 429가 나는데, 이 경우 알림 오류로만 기록하고 계속 동작합니다. sidekick 프로젝트는 수정하지 않습니다.
- 알림은 별도 스레드 큐로 보내므로 네트워크가 느려도 오디오 처리가 멈추지 않고, 전송 실패는 예외 없이 무시됩니다.

```powershell
$env:NTFY_TOKEN = "..."; $env:SIDEKICK_TOKEN = "..."; python -m soundwatch serve
```

## S21에서 열기

`getUserMedia`(마이크)는 **HTTPS 또는 localhost**에서만 동작합니다. s21-sidekick과 같은 방법을 쓰면 됩니다.

- **방법 A (권장) — Tailscale**: 서버는 `127.0.0.1`에 그대로 두고 PC에서 `tailscale serve --bg 8770` → S21 Chrome에서 `https://<pc이름>.<tailnet>.ts.net/#token=<토큰>` 을 엽니다. 토큰은 폰 localStorage에 저장되고 주소창에서는 지워집니다.
- **방법 B — Chrome 플래그(임시)**: `chrome://flags/#unsafely-treat-insecure-origin-as-secure`에 `http://<PC IP>:8770`을 넣고, 서버를 `python -m soundwatch serve --host 0.0.0.0`으로 실행. 같은 공유기 안에서만 쓰고, 토큰은 반드시 유지하세요(공용 와이파이 금지).
- `0.0.0.0` 바인딩은 LAN 전체에 포트를 여는 일입니다. 방화벽에서 신뢰하는 대역만 허용하세요.

열고 나서 **시작**을 누르면 에코 제거·잡음 억제·자동 이득을 끈 채(`getUserMedia` 제약) 마이크를 받아 AudioWorklet(없으면 ScriptProcessor)로 모아 **16 kHz 모노 Int16, 1초 단위**로 `POST /api/audio`를 보냅니다. 전송 실패 시 최대 30초 분량을 쌓아 두고 재시도합니다. 화면 켜짐 유지(Wake Lock)를 요청하니 충전기에 꽂고 세워 두세요. 일부 기기는 그래도 자동 이득을 완전히 끄지 못합니다.

서버 API (모두 `X-SoundWatch-Token` 또는 `Authorization: Bearer`, **쿼리스트링 토큰 불가**):

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/` | 폰 페이지 (비밀 없음) |
| POST | `/api/audio?session=&seq=&sr=16000` | Int16 LE PCM 본문 (기본 최대 512 KB) |
| GET | `/api/status` | 현재 레벨, 최근 인식, 템플릿 목록 |
| GET | `/api/ping` | 토큰 확인 |

수신이 2.5초 넘게 끊기면 그 구간은 '측정 안 됨'으로 처리됩니다(무음으로 채우지 않음).

> PC 마이크를 직접 쓰는 라이브 캡처는 이번 범위가 아닙니다. 나중에 `sounddevice`로 16 kHz 모노 블록을 받아 `Engine.feed()`에 넘기는 얇은 입력 어댑터를 추가하면 됩니다(선택 설치, 미구현).

## 3. 층간소음 기록

서버가 돌아가는 동안 100 ms 프레임마다 A-가중 레벨(LAeq,100ms 상당)을 계산해,

- 기준(`noise.threshold_db`, 기본 50 — **보정 전에는 상대값**) 이상이 `min_duration_ms`(300ms) 이상 이어지면 이벤트,
- `merge_gap_ms`(2초) 이내의 가까운 이벤트는 하나로 병합(발소리 연속 등), 내려올 때는 `hysteresis_db`(2 dB) 만큼 낮아야 종료,
- 이벤트마다 시작 시각·지속시간·최고 레벨(100 ms 프레임 최대)·구간 Leq·자동 구분(충격성/지속성 추정)을 sqlite(`data\soundwatch.db`)에 저장하고, **분 단위 집계**(1분 Leq, 측정 시간)도 저장합니다. 측정 시간 기록 덕분에 "이벤트 0건"과 "측정 안 함"을 구분할 수 있습니다.

```powershell
python -m soundwatch analyze 어젯밤.wav --log --start "2026-11-01 22:00"   # 이미 있는 녹음을 기록에 넣기
```

### 클립 저장 (기본 꺼짐, 선택)

`config.json`의 `clips.enabled: true`로 켜면 이벤트 앞뒤 3초(최대 30초)를 `data\clips\*.wav`로 저장하고 리포트 표에 파일명을 적습니다.

- **개인정보/법**: 다른 사람의 대화를 동의 없이 녹음하는 것은 법적 문제가 될 수 있습니다. 켜기 전에 관련 법령과 공동주택 규약을 직접 확인하세요. 이 설정은 법률 자문이 아닙니다.
- 완화 장치: ① 기본 꺼짐(레벨만 기록) ② `skip_speech`(기본 true): 말소리처럼 보이는 클립은 저장하지 않음 — **휴리스틱이라 완전하지 않습니다** ③ `lowpass_hz`(기본 500): 4차 저역통과로 대화 내용을 알아듣기 어렵게 함(쿵쿵 같은 저주파 충격음은 남음) ④ `retention_days`(기본 14일) 지난 클립은 서버 시작 시와 1시간마다 삭제, 수동은 `python -m soundwatch purge --days 7`.

## 4. 보정 (calibrate)

표시 dB = A-가중 dBFS + 120(공칭, 대략치) + **사용자 오프셋**. 보정하지 않으면 '상대값'입니다.

1. 실제 소음계(앱 말고 교정된 장비)를 폰 마이크 옆에 두고, 안정적인 소리(예: 선풍기, 백색소음)를 켭니다.
2. 소음계 값과 sound-watch가 보여 주는 값을 같은 순간에 읽습니다 (`serve`의 `/api/status` 또는 폰 화면의 'PC가 계산한 레벨', 또는 `analyze`).
3. 입력:

```powershell
python -m soundwatch calibrate --offset 3.5 --note "소음계 모델명, 거리 1m"
python -m soundwatch calibrate --meter 62.0 --shown 58.5      # 위와 같음 (62.0-58.5=+3.5)
python -m soundwatch calibrate                                 # 현재 상태 보기
python -m soundwatch calibrate --clear                         # 보정 해제
```

주의: 오프셋은 **하나의 값**이라 다른 음량·주파수에서는 오차가 남을 수 있고, 도구가 보정의 옳고 그름을 검증하지 않습니다. 오프셋을 나중에 바꾸면 과거 기록의 표시 값도 같이 바뀌므로(원본은 dBFS로 저장) 기록을 시작하기 전에 보정하세요. 기록 기준(`threshold_db`)은 표시 dB 기준이라 보정 후에는 값을 다시 정하세요.

## 5. 리포트

```powershell
python -m soundwatch report --week                      # 오늘 포함 최근 7일
python -m soundwatch report --days 30
python -m soundwatch report --from 2026-10-01 --to 2026-10-31 --out 10월.html
```

`data\reports\report_YYYYMMDD_YYYYMMDD.html` 과 `_events.csv`, `_daily.csv`(UTF-8 BOM, 엑셀에서 바로 열림)를 만듭니다.

HTML은 **단일 파일**(인라인 SVG/CSS, 외부 요청·스크립트 없음)이고 라이트/다크와 인쇄를 지원합니다. 내용: 요약 · 측정 설정/보정 상태 · 일별 표(측정 시간, 이벤트, 야간, 최고, 최대 1분 Leq, 1분 Leq 중앙값) · 주별(ISO 주) 표 · 일별 24시간 타임라인(빗금 = 측정 안 된 시간) · 이벤트별 최고 레벨 분포 · 시간대별 분포 · 일별 건수 · **야간(22:00–06:00) 건수와 목록** · 상위 이벤트 · 전체 목록 · **측정의 한계** · 데이터 지문(이벤트 CSV 해시).
야간 구분은 이벤트 **시작 시각**이 `night.start`~`night.end`(자정 넘김 지원, 기본 22:00–06:00)인지로 봅니다. 시간대는 `utc_offset_minutes`(기본 540 = 한국).

## 측정의 한계와 공식 절차

이 도구는 참고용 기록을 만듭니다. 리포트에도 같은 내용이 들어갑니다.

- **스마트폰 마이크는 교정된 소음계가 아닙니다.** 마이크 감도, 자동 이득, 주파수 특성, 케이스, 거치 위치, 실내 반사에 따라 같은 소리도 값이 달라집니다. A-가중은 소프트웨어 필터 근사입니다(16 kHz에서 20 Hz–7 kHz 해석식 대비 약 0.15 dB 이내로 설계·테스트, 7 kHz 위는 보장 안 함). 16비트/폰 마이크 자체 잡음 때문에 아주 조용한 값(대략 30 dB대 이하)은 신뢰할 수 없습니다.
- **보정하지 않은 값은 상대값**입니다(공칭 120은 대략치). 보정해도 단일 오프셋이며 검증되지 않습니다.
- 최고 레벨은 100 ms 프레임 평균 에너지의 최댓값으로, 공식 측정의 시간 가중 최고소음도와 정의가 다를 수 있습니다.
- 마이크 하나로는 소리가 **위층에서 왔는지** 알 수 없습니다. 집 안 생활 소음, 외부 소음, 본인이 낸 소리가 모두 기록될 수 있습니다.
- 폰 절전·네트워크 단절 등으로 기록이 끊길 수 있습니다. 일별 표의 '측정 시간'을 확인하세요.
- **공식 측정과 판단**은 관련 법령·기준에 따라 정해진 방법과 장비로 이루어지며, 층간소음 이웃사이센터 같은 층간소음 관리 기관, 관리주체(관리사무소), 층간소음관리위원회 등이 상담·측정·조정을 맡는 것으로 알려져 있습니다. 이 리포트는 그 절차를 대체하지 않고 법적 효력이나 증거능력을 보장하지 않습니다. **기준 수치·신청 절차·기관 안내는 개정될 수 있으니 이용 전에 최신 공식 안내를 직접 확인하세요.** (이 도구는 법적 기준 수치를 내장하거나 판정하지 않습니다.)

## 정확도 메모 (합성 소리 기준, 실제 가전 소리로는 검증하지 못함)

테스트용 합성음(두 음 초인종, 4음 세탁기 멜로디, 밥솥 삑삑삑, 전자레인지 '띵', 휘파람 주전자)을 백색/핑크 잡음 위에 얹어 측정한 값입니다.

| SNR(소리 대비 배경, 전체 파워 기준) | 정확히 1회·올바른 이름 | 다른 이름 오인 |
|---|---|---|
| +10 dB | 30/30 | 0 |
| 0 dB | 29/30 | 0 |
| -5 dB | 16/30 | 0 |
| -10 dB | 0/30 | 0 |

- 잡음만 12분(백색·핑크), 무음, 단일 음, 순서가 뒤집힌 초인종, 다른 음높이의 두 음, 다른 멜로디, 노크, 말소리 비슷한 합성음에서 오탐 0건이었습니다.
- 처리 속도: 5개 템플릿 기준 오디오 1초당 CPU 약 0.01초(numpy) / 0.02초(순수 파이썬) — 개발 PC 기준, 느린 PC에서는 달라집니다.
- **실제 환경은 더 어렵습니다**: 실제 가전 소리는 기종마다 다르고 방 울림, 폰 마이크의 자동 이득, TV·음악·말소리가 섞입니다. 등록은 반드시 **내 집·내 폰 마이크로** 하고, 오탐/미탐은 `--threshold`와 쿨다운으로 조정하세요. 노크 감지기는 그릇 부딪히는 소리 같은 반복 충격음에서 오탐할 수 있고, 물 끓는 소리 자체(비음정 잡음)는 휘파람이 나는 주전자만 템플릿으로 잡힙니다.

## 보안/프라이버시 요약

- 서버 기본 바인딩은 `127.0.0.1`, 모든 `/api/*`는 토큰 필요(상수 시간 비교), 본문 크기 제한, 미인증 요청 본문은 읽지 않음.
- 기본적으로 **오디오를 저장하지 않고** 레벨·이벤트 메타데이터만 기록합니다. 외부로 나가는 요청은 직접 켠 ntfy/sidekick 알림뿐이며, 알림에는 소리 이름과 문구만 들어갑니다(오디오 없음).
- `data\config.json`에는 서버 토큰이 있습니다(가능하면 파일 권한 0600). 공유/커밋하지 마세요.
